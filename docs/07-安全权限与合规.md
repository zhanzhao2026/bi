# 07 安全、权限与合规

---

## 1. 总体原则

1. **最小权限**:问数系统对数仓只读、只访问注册过的表;对用户按角色最小授权。
2. **纵深防御**:语义层(看不见即问不出)、编译层(权限谓词注入)、执行层(账号/AST/限流)三道防线,任一层失效不致越权。
3. **全程可审计**:问题→上下文→IR→SQL→结果→答案全链路留痕。
4. **数据边界明确**:LLM 数据流向有协议约束或私有化兜底。

## 2. 身份与访问控制

| 项 | 方案 |
|---|---|
| 用户体系 | 对接企业 SSO(OA 账号/OAuth2/LDAP),JWT 会话;不另建密码体系 |
| RBAC 角色 | `executive`(管理层:提问+历史+导出)、`analyst`(数据团队:+语义查看/评测)、`admin`(平台:语义发布/审计/配置)、`audit`(安全:只读审计) |
| 会话安全 | 内网部署+HTTPS;会话 30 分钟超时;敏感操作(语义发布)二次确认 |
| 导出控制 | 结果导出默认 CSV 带水印(用户+时间);是否允许导出由角色配置,默认 executive 可导、IM 端禁止 |

## 3. 数据权限

- **行级**:用户 profile 携带 scope 规则(品牌线/BU/区域),编译器注入 `WHERE brand_id IN (...)` 谓词(见 03 文档 §8);管理层默认全量,规则为空。规则来自企业组织系统,管理台可审。
- **列级**:语义对象标注 `acl`;未授权对象在检索阶段即被过滤(LLM 不可见),执行网关再校验 SQL 表列白名单,双重保险。
- **聚合阈值**:若开放明细下钻(P3),分组行数 < 5 的个体组自动聚合为"其他",防个人级信息泄露;用户级 PII 字段(手机号/收货地址等)**不进入**语义层,从源头不可问。
- **IM 端差异**:企微/飞书入口仅开放 P0 指标点位与趋势查询,不支持导出与明细。

## 4. 生成 SQL 的安全防线(执行网关)

| 防线 | 内容 |
|---|---|
| 1. 账号 | `bi_chat_ro` 只读账号,仅 ADS 库+白名单表 SELECT;网络层面限制来源 IP 为应用段 |
| 2. AST 校验 | 语法树解析:仅单条 SELECT;禁 `INTO OUTFILE`/UDF/多语句/注释拼接;表列∈语义层注册白名单 |
| 3. 资源硬限 | Workload Group `rg_bi_chat`(20% CPU/20% 内存/max 10 并发);`query_timeout=10s`;强制 `dt` 分区谓词;LIMIT ≤ 200 |
| 4. 注入防护 | 所有 filter 值经类型校验+参数化;枚举维度校验成员合法性 |
| 5. 审计 | 每条 SQL 执行记录:用户/问题ID/SQL/行数/耗时/水位,留存 ≥ 180 天 |

> 提示注入面评估:本系统输入仅来自少量内部用户,无外部不可信文本注入源;仍对用户输入做长度限制与控制字符清洗,且 LLM 输出永远不直接触库(IR 约束 + AST 校验),注入即使发生也不构成执行面。

## 5. 全链路审计模型

```json
{
  "trace_id": "tr_...", "user": "ceo_x", "ts": "...",
  "question_raw": "...", "question_norm": "...",
  "intent": "attribution", "clarifications": [],
  "semantic_ctx_digest": "v12/trade+funnel切片",
  "analysis_plan": { "...": "IR 列表与模式" },
  "sqls": [{ "sql": "...", "rows": 30, "latency_ms": 800 }],
  "answer_digest": "结论+图表+脚注哈希",
  "feedback": null, "eval_flags": ["grounding_pass"]
}
```

- 存 PostgreSQL,`trace_id` 贯穿日志;支持管理台全文检索(排查"那天给 CFO 的数是怎么算的")。
- 审计数据仅 `admin`/`audit` 角色可见,导出需审批。

## 6. LLM 数据边界(决策点,Phase 0 定案)

| 选项 | 数据流 | 合规要求 | 成本 | 适配 |
|---|---|---|---|---|
| A. 云端 API(私有协议/专属实例) | 问题+语义上下文出域(不含明细行数据,仅聚合上下文) | 供应商数据处理协议、日志留存承诺、(如需)脱敏网关 | 按量,月成本极低(QPS 极小) | 启动最快,效果上限高 |
| B. 私有化开源模型 | 全部数据不出内网 | 无出域 | GPU 一次性投入+运维 | 合规最稳;需 GPU 采购周期 |
| C. 混合 | 开发评测用 API;生产按合规要求切换 | 同上 | 居中 | **推荐默认路径** |

- 架构保障:Model Gateway 统一接口,切换=配置变更;语义上下文中**不含任何用户级明细**,仅指标/维度元数据,天然低敏。
- Embedding/重排模型一律本地部署(BGE-M3),不外呼。

## 7. 合规清单(上线检查项)

- [ ] LLM 供应商协议签署(DPA/日志/训练用途排除)或私有化部署验收
- [ ] 只读账号权限最小化复核 + 网络 ACL 审查
- [ ] AST 白名单与限流规则的渗透测试(尝试越权/全表扫描/注入)
- [ ] 审计日志留存与检索演练(180 天回溯任一答案)
- [ ] 语义层 ACL 配置复核(指标/维度可见性)
- [ ] 导出水印与 IM 端限制验证
- [ ] 数据出域清单评审(问题文本/语义元数据→云端模型的字段级说明)
