# 电商 AI 问数系统 —— 调研、架构设计与开发计划

> 项目代号:**AI 经营分析助手(BizInsight Chat)** | 文档版本:v1.0 | 日期:2026-11-07 | 状态:待评审

---

## 1. 一句话定位

面向企业管理层(小规模高价值用户)的 **AI 经营分析助手**:通过自然语言完成经营数据的查询、趋势分析、指标对比、多维下钻与归因解读。**不是 Text-to-SQL 工具**,而是"语义层约束下的分析智能体"——每个答案口径一致、可解释、可溯源。

## 2. 技术路线(已确认)

**Platform-native Semantic Context + 自建轻量语义层**

- 语义(指标口径/维度/业务规则/术语)以 YAML-as-code 形式**原生定义在本平台内**,由平台向 LLM 注入上下文、并将 LLM 输出编译为确定性 SQL,直查 StarRocks 3.1 既有数仓。
- **第一期不引入** Headless Semantic Layer(Cube / dbt MetricFlow 等),**不采用**完整 BI 平台;语义层保持轻量、可演进取舍。

## 4. 关键结论摘要

1. **准确率证据充分**:公开基准与厂商研究一致表明,引入语义层/语义模型可将 Text-to-SQL 执行准确率提升约 1.7~2 倍(BIRD 上 57%→78%),且在**建模良好的窄域内可达 ~100%**——这正是本系统选择"语义上下文 + 确定性编译"路线的核心依据。
2. **产品形态是分析助手,不是 SQL 翻译器**:8 个典型问题中有 5 个(类目下降排名、退款率归因、新老客对比、广告-销售相关性、环比解读)超出单条 SQL 能力,必须内建**分析模式库**(趋势异常、贡献度分解、漏斗、分群对比、恒等式拆解)。
3. **LLM 只负责"理解与表达",不负责"定义与计算"**:指标口径、聚合规则、权限过滤全部由语义层确定性实现;LLM 输出受 JSON Schema 约束(语义查询 IR),编译失败自动反馈重试。
4. **反幻觉硬约束**:答案中的每个数字只能来自已执行 SQL 的结果集,附指标定义、时间范围与"数据截至"水印;无法回答时坦诚拒答并发起澄清。
5. **数据侧以 ADS 预聚合层为主战场**:管理层问数 90% 命中日粒度聚合表,配合 StarRocks 分区分桶、HLL/Bitmap、Workload Group 隔离与结果缓存,P95 时延目标 < 8s。
6. **口径治理是最大项目风险,而非模型能力**:第 1 周即启动指标字典工作坊(GMV/客单价/退款率/新老客定义签收),语义层是唯一事实源。
7. **评测驱动开发**:Golden Set(100 题,口径经分析师核验)在 P0 阶段建立,所有 Prompt/模型/语义变更走 CI 回归;M1/M2/M3 准出门槛为 top-N 执行准确率 85%/90%/95%。
8. **模型策略:抽象网关 + 双轨 PoC**:云端 API(快速启动、效果上限)与私有化开源模型(数据不出域)在 Phase 0 用同一评测集对比定案;架构上模型可配置替换。
9. **体量小、架构要轻**:用户 ≤ 20 人、QPD ≤ 数百,单体内拆模块 + 少量独立服务即可,不为并发冗余设计;工程重心全在**语义质量与准确率**上。
10. **总工期约 19~20 周(≈4.5 个月)到生产可用**:MVP(基础问数)第 9 周内测,分析引擎第 15 周,生产化与验收第 19 周;团队 6~7 人。
