# 10 UI 交互原型设计(MVP 第一版)

> 配套交付:**可交互网页原型** [`prototype/bizinsight-chat-ui-prototype.html`](../prototype/bizinsight-chat-ui-prototype.html)(单文件自包含,双击离线可开)。
> 本版为重新设计的 **MVP 第一版**:严格区分**用户视角**与**后台管理视角**,整体风格干净清爽。用户端执行"零技术元素"铁律,后台面向数据/平台团队保留全部技术细节。

---

## 1. 双视角划分(MVP 核心决策)

| | 用户端(对话分析台) | 后台管理 |
|---|---|---|
| 使用者 | 管理层(executive),**完全不懂技术** | 数据团队(analyst)、平台管理员(admin)、安全审计(audit) |
| 设计铁律 | **界面不出现任何技术概念**:无 SQL、无 IR、无"语义检索/资源组/AST/trace/版本号"等字样 | 技术细节全量呈现:编译 SQL、行级谓词、资源配额、语义版本流水 |
| 信任表达 | 业务化三件套:「数据已核验」徽章 + 「数据截至 11-06 06:30」+ 口径**人话**弹层(如"客单价 = GMV ÷ 付款人数,同一人买多件只算一次") | 同上,另有 trace 全链路、grounding 计数、签收记录 |
| 过程透明 | 处理动画只讲业务步骤:**理解问题 → 查询数据 → 交叉核验(N 项数字与数据仓库一致)→ 生成分析** | 总览页与审计页可见真实管道(意图/检索/规划/编译执行/叙述) |

**用户端移除项**(相对内部工作稿):查询过程展开面板(IR/SQL)、"数字溯源 N/N 通过"、"X 条 SQL · X 秒"、指标 key(gmv/arppu)、口径版本号、"未触库"等技术徽章。口径签名/版本/编译 SQL 全部移入后台的语义管理抽屉。

## 2. 页面结构

```
BizInsight(单窗口,侧边栏切换两种视角)
├── 用户端:对话分析台(默认)
│   ├── 侧边栏:新对话 · 最近对话 · 「管理后台」入口 · 用户身份
│   ├── 空态:问候 + 昨日速览 4 卡(退款率告警卡可直接点入归因)+ 三组引导问法(查一查/看趋势/找原因)
│   ├── 对话:用户消息 / AI 答案卡 / 澄清卡 / 范围外说明卡
│   └── 输入:一句话提问框(Enter 发送)
└── 后台管理(侧边栏六页,每页带标题+职责说明)
    ├── 运营总览:4 项指标卡(提问/活跃/准确率/幻觉率)+ 数据就绪水位表 + DQC 告警 + 近期错例
    ├── 语义管理:指标字典(9 指标,行点击→口径抽屉含编译 SQL/维度/签收/版本历史)+ 维度与术语注册
    ├── 用户与权限:RBAC 矩阵(4 角色×7 能力)+ 用户行级数据范围 + 行级规则/邀请/导出策略入口
    ├── 评测与错例:4 项准出门槛 + 错例五类分布 + 错例清单(周会闭环)
    ├── 审计日志:trace 检索 + 行展开全链路(trace_id/semantic_ctx/权限注入/grounding/水位/SQL)
    └── 系统设置:Model Gateway 双轨路由 + 候选模型评测对比 + 语义版本发布流水 + 安全基线参数
```

IM 入口(企微/飞书)为 P3 范围,原型不含。

## 3. 用户端答案卡片解剖(核心组件)

自上而下:① 结论段(2~3 句人话,关键数字加粗、涨跌着色)→ ② KPI 卡/图表/明细表(按问题类型组合)→ ③ 边界标注(如"以上是相关性线索,建议业务侧确认")→ ④ 信任条:「数据已核验」+「数据截至」+ 口径芯片(点击弹人话定义)+ 👍👎 → ⑤ 「接着问」追问 chips(多轮继承时间窗/类目,并在回答中说明"已沿用上一轮")。

**处理动画**:发送后按业务四步逐项点亮(约 1.2s),完成后替换为答案卡——对管理层而言是"它在认真查数据、核对数字"的可感知过程,而非技术管道。

## 4. 关键交互规格

| 交互 | 行为 | 说明 |
|---|---|---|
| 速览告警卡 / 引导问题 | 直达演示场景(8 类典型问题全覆盖) | 冷启动引导 |
| 自由输入 | 关键词意图匹配;超范围(薪酬等)→ 友好说明 + 替代问法;明细请求 → "商品级明细暂未开放"说明 | 宁可不答,不猜数字 |
| 模糊提问「销售额怎么样」 | 澄清:确认时间范围 + "我会按 GMV 理解";选定后答案带「按 GMV 理解销售额」标注 | 假定显式可见 |
| 口径芯片 | 用户端弹**人话定义**(无表名/无版本号),后台弹**全量口径**(定义+签收) | 同一数据、两种受众 |
| 👍 / 👎 | 👍 "谢谢,已记录";👎 展开标签(口径不对/数字有误/没听懂我的问题/其他)→ "会安排复核" | 反馈闭环入口 |
| 后台-指标行 | 抽屉:定义/编译 SQL/可用维度/签收/版本历史(MR)/发起口径变更 | 语义治理 |
| 后台-审计行 | 展开 trace 全链路;检索框过滤演示 | 「那天给 CFO 的数怎么算的」回溯 |
| 后台各页按钮 | 行级规则编辑/邀请用户/切换云端兜底/发起新版本 等 → 演示 toast | 对接 07/03 文档流程 |

## 5. 视觉规范(干净清爽)

- **轻亮色系**:浅灰底 `#eef0f5` + 白卡 + 1px 浅描边 + 极轻投影;品牌渐变(靛蓝→紫)仅用于 Logo、头像、发送按钮与激活态;图表系列色蓝/青,涨跌红绿仅作语义色。
- **留白与层次**:基础字号 14px,卡片圆角 13px,答案气泡最大宽 820px;页面级留白 ≥26px;表格无竖线、仅横向细分隔。
- **数字**:所有指标数字 tabular-nums;KPI 值 20px;永不小于 11px。
- **深浅双主题**:`light-dark()` 自适应,已按浅色/深色双分支截图验收。
- **实现要点(给前端)**:全局重置必须用零权重选择器(`:where()`),否则 ID 级重置会静默清空组件内边距与边框(本原型曾因此整版样式塌陷,已修复)。

## 6. 前端实现建议(P1 启动直接引用)

1. React + TS 单页;消息流由 Orchestrator **SSE 事件驱动**,用户端按事件增量渲染;后台页面为常规 REST + 表格。
2. 组件清单:用户端 `ChatShell / AnswerCard(M1~M8 变体)/ ClarifyCard / ScopeNoticeCard / CaliberPopover / TrustBar / FollowUpChips / FeedbackBar`;后台 `AdminShell / OverviewPage / SemanticPage(+MetricDrawer) / PermPage / EvalPage / AuditPage / SettingsPage`。
3. 图表生产用 ECharts 封装主题(原型内置 SVG 实现即图表规格的"活文档")。
4. 无障碍:语义 button/table、答案流 `aria-live`、图表 title/desc、Enter 发送/Esc 关弹层。

## 8. 原型演示脚本(评审会用)

1. 用户端空态 → 点速览区「近30天退款率 ⚠」→ 看业务化处理动画 → 归因瀑布 + 类目贡献表 + 线索标注;
2. 追问「只看美妆的退款率走势」→ 多轮继承;再问「具体是哪些商品」→ 明细边界说明;
3. 输入「销售额怎么样」→ 澄清 → 选「和上月比」→ 答案带「按 GMV 理解」标注;
4. 输入「员工平均工资」→ 范围外说明;点口径芯片 → 人话定义;
5. 侧边栏切「管理后台」→ 运营总览(门槛/水位/告警)→ 语义管理点开「客单价」抽屉(编译 SQL/签收/版本)→ 评测与错例 → 审计日志检索「退款」展开 trace → 系统设置(模型路由/版本流水)。
